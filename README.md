# sql_analysis_agent

Агент для аналитики по таблицам: вопрос на естественном языке → SQL → выполнение →
самоисправление по ответам базы → ответ с таблицей. Построен на LangGraph, работает
локально через Ollama.

> **Данные синтетические.** БД сгенерирована скриптом `sqlagent/db/generate.py`
> (Faker + random, seed=42), реальных данных банка в проекте нет.

## Данные

SQLite, 7 таблиц в двух доменах:

- **Инкассация:** `branches`, `atms`, `routes`, `collections`
- **Закупки:** `suppliers`, `contracts`, `invoices`

Схема с комментариями описана в [`sqlagent/db/schema.sql`](sqlagent/db/schema.sql).
SQLite хранит эти комментарии в `sqlite_master`, поэтому агент видит их вместе со схемой.

В данные специально заложены аномалии, список генератор пишет в `data/anomalies.json`:

| Аномалия | Как выглядит |
|---|---|
| Недостачи на маршруте | Один маршрут с июня систематически сдаёт меньше, чем показывают счётчики банкоматов |
| Дробление закупки | 7 договоров чуть ниже порога закупки без конкурса, поставщик зарегистрирован за 2 недели до первого |
| Дубли счетов | Тот же номер и сумма по тому же договору, оплачены дважды |
| Грязные значения | `г. Москва` / `москва` / `Москва`; NULL в суммах отменённых выездов |

## Запуск

```bash
uv sync
uv run python -m sqlagent.db.generate   # → data/bank.db, data/anomalies.json
uv run python -m sqlagent "Сколько банкоматов в Москве?"
```

## Оценка

Набор вопросов: [`eval/questions.yaml`](eval/questions.yaml). В нём 43 вопроса в 9 категориях:
простые, грязные значения, регистр кириллицы, даты, смысл колонок, аномалии, многошаговые,
вопросы без ответа в базе и опасные запросы. У каждого вопроса есть эталонный SQL или
пометка, что правильный ответ — отказ.

```bash
uv run pytest -q                                   # тесты; эталоны проверяются на заглушке LLM
uv run python -m sqlagent.eval.run --name 7b       # прогон → eval/results/7b.jsonl
uv run python -m sqlagent.eval.report              # таблицы → eval/results/report.md
```

Метрики:
- **Execution accuracy.** Результат запроса совпадает с эталонным: лишние колонки допустимы, знак числа не важен.
- **Точность первой попытки и итоговая.** Первый SQL агента — это ответ одной LLM без самоисправления, поэтому бейзлайн получается из того же прогона.
- **Исправил / испортил.** Сколько ответов агент спас, а сколько ухудшил «исправлениями».
- **Срабатывания проверок.** Какая проверка отправила SQL на исправление и не была ли это ложная тревога.
- **Ключевые факты** в текстовом ответе и **числа не из таблицы** (выдуманные цифры).
- **Отказы:** правильные и ложные.
- **Затраты:** время p50/p95, вызовы LLM, токены, время на один правильный ответ.
